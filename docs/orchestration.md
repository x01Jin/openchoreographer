# Orchestration

The orchestrator runs a loop: restate the goal, inspect what the task needs, split the work into independent tasks with clear boundaries, delegate each to the role that owns it, verify the diff, and report what was done with the evidence. It reads with read, glob, grep, webfetch, websearch, and the [diff](diff.md) tool, and it changes files only through workers.

Delegation goes through the built-in `subagent` tool with `agent`, a short `description`, and a complete `prompt` stating the goal, files, constraints, acceptance criteria, and expected return format. Every worker task states the acceptance check the worker must run before returning. Independent work runs as background subagents; each call returns a sessionID immediately, and passing it back continues that same child. Only one writer touches a file set at a time unless the sets are disjoint, and `maxParallel` is a prompt-level hint that enforces nothing. Tell each worker what it owns and what it must not touch, and do not ask two workers to edit the same file unless the file is split by clear boundaries.

Effort is tiered, and a tier is a ceiling, not a target. The orchestrator picks the tier before spawning anything and re-checks it against the `Risk:` line the diff tool returns. Tier 0 (no file change) spawns nothing. Tier 1 (one mechanical file) is one worker with no reviewer. Tier 2 (two to five files or new tests) adds the correctness lens only. Tier 3 (more than five files or any risk signal) adds correctness plus security, plus `tester` when behavior changed. When the diff is smaller than the tier assumed, the orchestrator does not spend the remainder. Tier 2 and Tier 3 UI work runs `designer` before `frontend`; behavior changes run `writer` before the final verification. See [reviews](reviews.md) for the review side and [models](models.md) for model selection.

A worker that fails is retried once in the same role with a narrower task. If it fails again, the orchestrator reports that role as unavailable, with the failure and the model it ran on, and never hands its work to a different role. A scope correction (`BLOCKED: outside <role> scope`) is not a failure: the task moves once to the named role. An override refusal (`BLOCKED: task attempted to override role scope`) stops that task with no retry.

When `explore` ran, its map is pasted verbatim into child prompts so children do not rediscover the tree. MCP tools are routed by agent: a code-intelligence server for call paths, `context7` for library APIs, a browser server for UI behavior that code cannot confirm. MCP tools that change external state belong to the worker that owns the task, never to the read-only orchestrator.

Results are clipped, not re-read per child. Each text part of a foreground subagent result over 4000 characters keeps its head and tail with a marker giving the dropped count. For a finished batch the orchestrator reads the diff once after the batch, narrowing with `path` when it spans many files and passing `context: 0` unless the patch is ambiguous. A file is read directly only when the diff is ambiguous. No claim is accepted without evidence.
