# Sidebar and settings dialog

## Sidebar

The sidebar shows an `AGENTS & MODELS` block with three sections. `PRIMARY` lists the host's primary agents. `WORKERS` and `REVIEWERS` list only this plugin's thirteen subagents (eight workers, five reviewers); built-in host subagents are not listed. Disabled subagents are hidden from the `WORKERS` and `REVIEWERS` sections but stay in the settings rows and in the `PRIMARY`/`FALLBACK` model sections. Each row shows the agent name and its active model. Below the roster, `RUNNING` lists running child sessions of the current session, and `TODOS` lists the session's todo items with a done/total count. RUNNING rows are clickable: clicking a row navigates to that child session with the router. Each row keeps the same two-column indent as AGENTS rows so names stay aligned, shows `↗` immediately after the agent name, and keeps the model at the right edge. The row brightens on hover: the arrow and model go from faint/muted to the base text color while the name keeps its agent color and turns bold. Neither RUNNING nor roster rows are focusable, so there is no keyboard shortcut for either; both are mouse-only. A row running on a fallback model prefixes its model with `↳ ` in `#f5a97f`, which is the model the agent's next spawn will use rather than the model a running child is currently using; a row on its primary looks as before. Clicking the model cell of a fallback row arms a confirm: the cell reads `switch primary?` in the base colour, bold, and a second click on that cell restores the primary for every agent sharing those models at once (each returns to its own primary; agents on other models are unaffected), after which the failure ladder applies again on the next failure; clicking another fallback row moves the confirm there, any other section or session click disarms it, and there is no timer. While the restore call is in flight the cell keeps the fallback name and ignores clicks; if the restore fails the cell stays on the fallback and a warning toast reads `Could not restore primary model: server plugin unreachable`. The model column stays 15 cells wide and truncates, with the `↳ ` prefix counted inside the width.

Two switches control what is visible. The `TODO panel` switch hides the TODOS section; `todowrite` and `todoread` keep working, so the list returns intact when it is turned back on. The `Agent roster` switch hides the AGENTS & MODELS block; the RUNNING list stays visible while subagents run, even with the roster hidden. Two more switches control animation: `TODO animations` (the colour cycle on in-progress todo rows) and `RUNNING animations` (the flowing RUNNING label). The RUNNING header animation is a per-character palette sweep moving left to right, one step every 220 ms; with animations off the header is a solid color. Turning an animation off stops its timer.

## Settings dialog

`/choreographer` opens the dialog. It has `ANIMATIONS` and `INTERFACE` rows (the four switches above), one `SUBAGENT TOGGLE AND STEPS` row per managed agent with its step budget, and `PRIMARY MODELS` and `FALLBACK MODELS` sections for the thirteen subagents. The `INTERFACE` section ends with a `Max parallel` stepper after `Agent roster` and before `SUBAGENT TOGGLE AND STEPS`, adjusting by 1 with `←`/`→` or `−`/`+`; it is always a stored number, 1-8 with default 4, and `r` resets it to 4. The `default N` hint sits to the left of the `− value +` stepper for both `Max parallel` and step rows, showing only when the stored value differs from the default. Each subagent row has a checkbox (`[x]` enabled, `[ ]` disabled); the orchestrator row has none. A disabled row shows a dimmed id and an `off` tag. When all 13 subagents are off, a faint line reads `all subagents off — orchestrator runs alone`. Disabled subagents stay in the settings rows and in the `PRIMARY`/`FALLBACK` model sections. Each model section groups its rows under `WORKERS` and `REVIEWERS` subheaders with one bulk row per group (`all workers`, `all reviewers`). A bulk row shows the shared model name when its members agree and `custom` when they differ. A primary row with no override shows the agent's configured model or `inherit`; a fallback row with no override shows `none`.

Arrow keys move, left and right change a step budget by 5 even when the row is disabled and `Max parallel` by 1, enter opens a picker or confirms, space toggles the focused subagent row on/off (confirms elsewhere), and escape closes the dialog (or backs out of the picker first, clearing the search query before that when one is typed). Click a row to select it, click its checkbox to toggle it, click `−` or `+` to change a budget, and use the wheel to scroll. The footer reads `↑↓ move · ←→ ±1/±5 · enter pick · space on/off · r reset · esc close` and `click checkbox toggles · − / + adjusts steps even when off`. `r` resets whatever the row holds: a step budget back to its default, a primary or fallback row's override cleared, or every member's override cleared on a bulk row. The in-dialog model picker groups models by provider; entering a bulk row applies the choice to every agent in the group at once, replacing per-agent overrides. The picker has a search bar: typing filters the models live, case-insensitive over the name, the provider, and `provider/model`. Provider headers stay only while they have matches; zero matches shows `no matches for "<query>"` and enter does nothing. Up and down moves and stages a model, enter confirms, and escape clears the query first, then backs out to the settings list. While the picker is open `r` and space type into the search instead of resetting or confirming; in the list view `r` still clears an override. Returning to the list keeps the previous scroll position and row selection.

Step budgets persist to the agent definition file (`~/.config/opencode/agents/<id>.md`, `$OPENCODE_CONFIG_DIR/agents/<id>.md` when that variable is set, or `.opencode/agents` when the project has one) and the host reloads the agent when that file changes. Disabling a subagent moves its installed definition aside to `<id>.md.disabled` in the same directory so the host stops loading it; enabling moves it back and restores its rules in the installed orchestrator prompt. Disabling also removes that agent's rules from the installed orchestrator prompt. Toggling also regenerates every enabled worker's `Team:` line to list only the enabled worker ids. The step budget survives the move and stays editable while off, with writes going to the `.md.disabled` file. Model overrides persist to the plugin's own settings storage and write no file. Values are clamped to 1-2000 steps. When the server half is not running, the animation and interface toggles still apply from the TUI's own storage, the agent rows are unavailable, and the picker is read-only.
